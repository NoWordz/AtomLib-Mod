# AtomLib 0.6.0 前端契约锁设计与实施方案

日期：2026-11-17；收口更新：2026-11-18。第二版已授权并按R1—R9修订。阶段一、二的小场景机制门已闭合，阶段三真实两页完整接入未完成；现按用户要求停止续作、提交本地开发检查点。实际状态以 docs/STATUS.md 和[交付检查点](../../verification/2026-11-18-frontend-contract-lock-delivery-checkpoint.md)为准。用户已认可原有设置页完整前端，不用重新选版本；精确参照见[参照定位](../../verification/2026-11-17-frontend-contract-lock-reference.md)。

正式名称：**前端契约锁**；简称：**前端锁**；英文：**Frontend Contract Lock，FCL**。名称已由用户确认；本地版本已为0.6.0开发候选，公开稳定版仍为0.5.0，未发布本轮候选。

**目标：** 将“沿用指定页面的完整前端”转化为可执行契约，拦住擅自新增风格、非法组合、页面手算布局和交互遗漏，并用真实消费者验证。

**架构：** 在现有 core / runtime / ui 上增加族群契约、受约束的页面构建入口和验证能力。继续使用 Yoga、LayoutSnapshot / PresentationFrame、UiSession、主题快照与现有动画机制，不再建立一套布局、输入或渲染引擎。

**技术基础：** Java 17 公共模块、现有 Gradle / JUnit / Python 检查工具，现有 Skija / Yoga；Forge 1.20.1、Fabric / NeoForge 1.21.1 分发与输入适配保持既有边界。

## 1. 范围与交付边界

原方案阶段仅交付文档。2026-11-17 用户随后明确授权由唯一实施代理按本方案实施，先验证阶段一可行性，保留所有 WIP；不创建更多代理、不转交新会话。AtomChat 接入须先核对专项所有权；本次实施授权不包含部署、启动／停止游戏、提交、推送或公开发布。

0.6.0 的目标交付包括：

- 可按项目启用的前端锁，以及族群、配方、页面契约和明确的设计变更流程。
- 严格页面构建入口、源码边界检查、契约完整性检查、动态与视觉回归。
- 可独立获取的构建检查制品及 Gradle 接入，消费者不需要 AtomLib 源码目录。
- 一个真实“标杆页面＋复用页面”闭环，覆盖所选页面完整前端。
- 故意植入缺陷后能报红的负例及恢复后的正例。
- 开发指南、消费者接入说明、检查报告和阶段性覆盖说明。

首版不做全量 AtomChat UI 迁移、通用审美评分、任意代码的形式化验证、代理权限沙箱或仓库权限系统。性能作为独立验收项，不要求每个族群声明一套耗时或显存预算。

保留未启用锁的底层入口及旧消费者兼容路径，但这些入口不能成为受锁页面的旁路。既有页面可以逐步迁移，必须明确列出尚未覆盖的范围。共享库升级不自动升级项目已批准的设计定义。

首版完整检查范围为 Java 17 / 21 源码及上述三端 Minecraft 宿主，含实际采用的路由、Screen、HUD、模态和页面外层合成入口。JDK 检查器须使用宿主对应的编译工具链。Kotlin 等其他语言、未知生成器和未适配入口不能静默跳过：启用项目必须报告 UNSUPPORTED / UNCOVERED 并阻断，不能宣称这些范围已受锁。增加支持属于后续扩展，不缩小已选真实试点的完整流程。

## 4. 概念与单一正本

### 4.1 基础族群

族群是项目定义的受约束设计集合，包含明确成员、版本、作用域、引用关系和可开放参数。首个试点按实际需要覆盖：

- 颜色与语义颜色、材质、阴影、描边和圆角。
- 字体角色、字号、行高、尺寸与间距档位。
- 图标集合、图标角色、占位与实际图形边界规则。
- 悬停、按压、高亮、点击反馈、弹跳及其他已存在的动效。
- 布局规则、自适应约束、内容插槽与降级表现。
- 参照中已有的 UI 声音反馈：资源／事件绑定、触发时机、音量／音高／通道、同动作仲裁、节流／取消和明确无声状态。按实际参照启用，不给所有组件强加声音。

“派生”指沿用已有定义并声明变化；“组合”指把基础能力绑定为一个完整配方。两者都必须显式表达来源，不能复制后假装仍与原定义联动。

项目间定义隔离，不使用进程级可变全局“当前风格”。项目内部允许显式共享、继承和作用域覆盖；循环、歧义和冲突报错，不静默按加载顺序选择。

### 4.2 组件配方与角色基线

组件配方绑定结构、部件、材质、档位、状态、交互反馈、动效、内容插槽和降级。配方实例化后，由同一组件实现处理这些职责，页面不逐项接线。

角色基线由项目的已批准设计定义确定。库负责完整性结构与校验，不把 AtomChat 的水波或弹跳强加给所有项目。交互角色必须与实际能力核对，不能把带点击动作的组件标成纯展示以逃避要求。

每个要求必须明确落入：必需、具备可判定条件的条件触发、该角色允许且附有依据的不适用。未填写、引用不存在或条件未定义均为错误。状态叠加、快速反转、取消和禁用等按该组件实际能力声明检查，不要求穷举整个 UI 的笛卡尔组合。

### 4.3 页面契约

页面契约记录参照前端、允许组件配方、布局规则、开放参数、动态内容插槽及必需验证场景。参照前端必须指向明确的获批定义，不能只写“风格接近设置页”。

页面可以改变业务文案、数据、分组、数量和获批规则内的排列。可使用已批准配方的合法变体，不得新增基础能力组合、局部皮肤覆盖或匿名样式。

页面声明、组件依赖与运行时实际生成的组件共同核对覆盖范围。虚拟列表核对条目类型与能力，不要求把所有业务数据一次性渲染；隐藏、折叠、禁用和空态等必需分支要有场景。报告区分未声明、未覆盖、已验证和明确未迁移。

### 4.4 定义的存储与解析

Java 类型化声明是设计的作者输入，与页面业务源码分开存放；经构建阶段一次解析，生成确定、不可变的规范化设计包，作为审核、打包和运行共同消费的设计结果。作者输入与生成结果不双重手工维护，游戏启动时不重新执行作者输入。

作者输入只允许字面量、显式引用、有限的纯构建器与受控表达式，不允许读取时钟、随机数、环境变量、系统属性、文件、网络或捕获任意回调。调用无法确认来源的辅助函数时报未支持，不推断其“应该纯净”。模型不依赖 Minecraft 或 Skija；规范化结果只包含数据与已定义操作，不增加通用脚本解释器。

设计包至少包含：项目命名空间、设计版本、格式版本、语义配置版本、族群及配方闭包、角色基线、参数与条件定义、实现绑定、素材集合、场景要求和基准引用。同一命名空间与设计版本不能表示两份不同的规范化内容。构建清单与运行资源由同一解析结果生成，并验证解码后的内容一致；序列化编码的具体选择属于阶段一的技术验证，不能改变这些约束。

已开放的主题色等运行时参数以声明的参数引用进入设计包，在运行时按范围求值；环境差异只能通过命名条件进入，例如已经定义的模糊可用性。普通环境、启动参数或机器路径不得暗中改变同一版本的定义。构建侧导出的解析结果、打包内容和运行时注册表需逐层对应，不能只比作者源码或 ID。

正式注册表只接收已批准定义，页面取得只读句柄。字符串 ID 不是授权机制：引用必须解析到现有定义，并经过页面允许范围校验。构建报告输出来源和依赖关系，不用相同的生成结果同时充当实现与独立验收依据。

句柄绑定所属项目、设计版本及成员身份，不能跨注册表按同名 ID 偷换。每窗口可变交互状态与共享不可变定义分开；运行时只读注册表不接受页面自行注册或替换实现。

草稿使用独立的开发 source set / 资源入口，默认不进入发布打包；正式引用、资源清单和产物检查共同拒绝草稿依赖，包括仅通过资源间接进入的情况。

### 4.5 设计版本与库版本的兼容边界

分别管理库运行版本、设计包格式版本、项目设计版本及语义配置版本。语义配置覆盖可观察的布局解释、尺寸派生、材质算法、颜色派生、动画曲线与时间规则、状态叠加和降级选择，不能仅固定 palette、MotionSpec 数值或族群 ID。

配方必须绑定明确的组件实现及语义配置，禁止“相同 ID 始终指向最新实现”。状态叠加顺序、子动作与容器反馈归属也属于该绑定，不能因库升级改成双重水波或双重按压。实现中仍可保留必要计算，但其可观察规则不能绕过设计版本管理。

分发制品声明支持的格式与语义配置集合。机制修复可共享后端和资源代码，但必须用旧设计包验证其支持的旧语义，不能通过更新旧基准接受新表现。需要改变可观察规则时建立新语义配置和设计候选；无法继续支持某版本时报告 INCOMPATIBLE_PROFILE 并给出迁移要求，不自动替换成最新版，也不把不兼容称为普通升级。

首版不追溯宣称旧 0.4 / 0.5 自由调用已经具有此保证，也不要求复制整套旧引擎。阶段一从获批真实标杆建立首个语义配置；以后兼容验证始终带着该设计包、素材与独立参照运行。

## 5. 页面入口与运行时约束

受锁页面只描述内容、业务绑定、动作、获批组件与布局组合。严格 API 的视觉参数使用可解析引用或受控句柄，不提供随手传 ARGB、圆角、动画时长、Rect、画布回调等便利重载。

业务数值不等于视觉数值。例如滑条所编辑的音量、输入值上下限和文本内容仍属于业务模型；页面组件宽高、间距和动画参数则必须来自契约，不能通过“一切数字都禁止”的规则混淆两者。

页面描述解析后进入既有 LayoutTree / Yoga，再产生同一份 PresentationFrame 供绘制、命中、焦点与滚动使用。动画变换和命中逆变换必须同源；必需动效使用统一帧时钟，不允许页面自建第二个时钟或以预览开关关闭它们。

组件内部的图标绘制、光标计算、拖动与内容测量可以使用必要数学运算。它们属于明确的组件实现范围，必须有相应行为和渲染检查，不能仅因把页面计算搬到任意 helper 就被视为合法。

自适应尺寸由获批规则计算：内容测量、父约束、伸缩、换行和已定义上下限均可产生连续结果。页面临时添加一个高度、偏移或补偿公式属于越界。

运行时参数按契约校验范围及派生关系，同帧冻结快照。合法设置变化不是新风格；页面不能借此逐组件修改未开放参数。项目内获批设计更新重新验证依赖者；升级库不自动选择新的设计版本。

业务动作与网络、存储继续归宿主。前端锁核对动作与交互能力的绑定，不把服务端配置事务、权限和持久化逻辑搬进组件框架。

### 5.1 布局单位、坐标转换与变换顺序

严格布局值和文本测量统一使用逻辑单位 u，令牌记录单位与用途。设备像素只用于输出和明确的像素约束；窗口坐标、MC GUI 坐标及设备像素不能作为无单位数值直接传给组件。

宿主适配器明确输入回调所属坐标空间及 viewport 含义，一次性转换到统一宿主 UI 空间。已经是 MC GUI 坐标的输入不得再乘一次 GUI 缩放。字体按逻辑字号测量；禁止把设备像素测量当成逻辑尺寸再次缩放。

完整变换链按层次组合为“节点局部 → 内容 → 页面 → 宿主 UI → 设备像素”；内容缩放、滚动、页面切换及节点反馈分别由所属层负责。绘制按链正向使用，命中从同一成功呈现帧取得逆变换。每一项缩放只能应用一次，组件不能重新调用旧 s() 或重复乘 uiScale / contentScale。

阶段一必须记录现有适配器实际转换关系，阶段二以单位或明确边界类型表达，不能让页面选择换算公式。验收包括非默认 GUI 缩放、窗口变化、内容缩放、滚动与动画中间态；需要比较实际绘制边界与输入落点，不能只比较两份同源但共同错误的矩形数据。

## 6. 素材、图标与降级

设计素材有明确身份、来源集合、用途和允许的呈现方式。图标检查插槽尺寸、实际图形边界、缩放、留白、对齐与获批的光学修正；不能只依据 SVG viewBox 或纹理画布尺寸声称对齐。合法集合内可以按业务选择不同图标，不允许页面修改图形或临时加偏移。

头像、表情包、用户图片和业务文本通过内容插槽加载。插槽明确几何、裁剪、层级与交互职责。内容句柄不能进入材质槽、取得任意画布回调、越界绘制、创建组件身份或新增命中区域；这些是可检查的能力边界。

业务图片可以描绘按钮、卡片或完整 UI 截图，框架不判断其图像语义。合法头像即使内容是一张界面截图也应通过；把同一内容句柄用作卡片材质或任意页面背景应失败。不引入图像语义审查或相似度判分来解决插槽越权。

图标库版本、字体方案和纹理改变属于设计变更。人工判断新素材是否协调，获批后再建立可重复检查的规范；不引入“风格相似度分数”作为批准依据。

模糊不可用、资源缺失等实际支持的异常条件，必须绑定已批准的降级方案并验证。未定义的降级是契约错误；发布运行时应保留仍有效的状态或报告不可用，不擅自换库默认皮肤，也不把可预期资源失败升级为整个游戏崩溃。

## 7. 工程约束与批准边界

普通页面任务只能消费已批准正本。新族群、配方、覆盖、基础规则、源码边界、检查器、基准和容差的变化都单独呈现，不能混进“修复页面”后自动认可。

CI 不通过读取一句“approved=true”来理解聊天授权。正式批准依据是项目所有者明确认可并纳入设计正本的版本，普通构建只消费这一来源。作者输入、候选清单或当前工作树的自述不构成批准依据。

用户已授权的范围不逐参数重复确认。例如“只沿用材质，其他重新设计”允许在该范围探索；它不授权修改原材质、免除完整性基线或影响其他页面。最终设计和新增视觉基准按既定流程审定。

这是工程约束，不宣称抵御拥有全部源码、CI 与合入权限的恶意修改。不新增 SHA 保护清单、独立信任副本、只读文件锁或提交钩子。

### 7.1 普通检查、候选检查与状态

项目接入配置明确记录：已审定设计来源及版本、对应的批准索引、源码与宿主范围、角色基线、遗留入口登记、检查器协议及语义配置。正式来源可以是项目已审定版本中的设计包，或已审定分发坐标，不允许 latest、当前候选输出或 HEAD 工作树隐式替代。

CI 普通模式默认从 CI 事件确定的 PR 目标分支读取既有批准索引；非 PR 构建使用项目已审定的显式设计版本或分发坐标，不能根据当前作者源码自行选择。首次初始化也须经所有者审定，不能把“没有旧版本”当成自动批准。它比较候选对批准索引、基线来源、遗留登记、构建接线及检查器配置的改动。普通页面变更不能修改这些选择来让新定义自动变为正式定义。离线没有可辨认的已审定输入时，输出缺少依据并阻断，不退回使用工作树自证。

| 检查状态 | 普通验收结果 | 允许用途 |
| --- | --- | --- |
| APPROVED_VALID | 成功 | 使用已审定版本且全部适用检查通过的普通页面。 |
| CANDIDATE_VALID | 待设计审查，普通验收阻断 | 设计候选已通过技术检查，仅用于带候选标记的报告和隔离预览。 |
| INVALID | 失败 | 契约、来源、行为、渲染或制品违反规则。 |
| UNCOVERED / UNSUPPORTED / MISSING_EVIDENCE / INCOMPATIBLE_PROFILE | 失败 | 未覆盖、未支持、缺依据或不兼容；不能转成成功或静默跳过。 |

检查器内部候选命令可以正常完成并生成报告，但 Gradle 普通 check / build / 正式打包任务必须传播“待设计审查”的阻断结果，不能只看子进程退出正常就把 CANDIDATE_VALID 当成 APPROVED_VALID。草稿仅通过独立开发预览入口构建，不能获得正式发布资格。

### 7.2 设计晋级顺序与批准范围

设计变化先输出旧版与候选的规范化差异，覆盖定义、实现绑定、素材、语义配置、条件、基准、容差及受影响消费者。项目所有者确认的是这组具体差异和范围；聊天中的宽泛设计授权允许探索，不自动批准未展示的最终结果。

经明确认可后，设计包与批准索引进入项目正本，成为下一阶段普通构建的已审定输入；然后页面才能以 APPROVED_VALID 使用新版本。不强制不同 PR，但两阶段必须有可识别的先后状态，不能在同一次候选执行中同时产生批准依据和宣称依据已被认可。相同批次需要分别保留设计审定步骤与基于审定结果的最终检查。

晋级依据沿用正常版本管理、所有者审查与现有 CI 的认可流程，不新增账号权限隔离。若无法在某个构建环境辨别设计晋级是否完成，只能交付候选报告，不能由代理写一个布尔字段代替外部认可。

## 8. 检查与诊断设计

### 8.1 源码边界和覆盖

首选使用 JDK 编译树和符号解析验证严格入口的实际依赖，结合受控句柄减少自由参数入口。原型先验证：直接调用、静态导入、完全限定名、方法引用和 helper 间接调用能否正确定位。不能仅用搜索十六进制、禁用乘加或匹配类名代替来源检查。

严格页面、页面工厂与组件注册建立可枚举入口，并与消费者已存在的路由接入点交叉检查。覆盖不是逐类注解的自愿登记：检查器枚举启用项目全部生产 source set，包括生成源码，结合宿主适配器识别 Screen / HUD / 模态注册、页面路由分支、渲染与输入回调、外层 header / overlay 及原生 UI 绘制调用。新增入口不能因漏写一个注解或漏放一个目录就退出覆盖。调用未知 UI 工厂、无法解析的样式来源或不受约束的绘制回调，输出未覆盖错误，而不是默认为通过。

遗留豁免以已审定的具体路由键、工厂／方法符号及 UI 调用结构登记，不按目录、整个文件或任意前缀豁免。对同一旧文件增加路由、分支、回调、绘制调用或新的 UI 依赖，必须判为新增／变化的 UI 接入。被登记的旧 UI 方法发生相关结构变化时先输出 LEGACY_UI_CHANGED；不能自动把新结构纳入豁免。

未改动的旧界面可继续运行。确属既有界面的修复，可经明确审查更新对应遗留记录；这不允许把新增页面或新组件改称遗留。普通业务改动若未改变 UI 调用结构不要求迁移整个文件。新功能必须经严格入口构建；无法可靠区分的修改报告待分类，不能默认放行。

宿主外壳的旧代码同样受变化检测约束。只迁移 body 时不得宣称整个页面已覆盖，必须列出 header、overlay、模态及输入链的状态。真实试点要求其选定完整前端均有明确的契约或受审定合成绑定，并验证实际外层，不允许把新风格画到受锁 body 之外。

允许业务 helper，但其进入 UI 构建的边界必须是受控 API。组件实现和旧入口有明确来源范围，严格页面不能经由包装调用旧入口。检查器不承诺证明任意反射、动态类加载和运行时生成代码；严格构建路径不支持以这些方式引入未知 UI。

缺清单、缺场景、扫描零命中、测试全跳过、缺渲染输出和陈旧报告均不能返回成功。应验证预期入口及场景集合，而不是只设一个容易凑数的总数量阈值。

如果阶段一无法证明同文件新增路由和旧外壳新增绘制能被识别，项目级“所有新增 UI 受锁”的目标尚未达到；不得以缩窄扫描目录或只检查试点注解作为替代。对未知宿主只能声明未支持并阻断，不能据此把该项目标成完整启用。

### 8.2 动态验证

从生产页面入口绑定可控业务数据、输入序列和帧时钟，执行必需状态与转换。检查实际输入结果、动画轨迹、绘制及命中，而非只记录“注册过 hover / ripple”。点击内层动作、拖动取消、失焦、折叠期间捕获、切换反转等按试点实际能力覆盖。

角色基线和必需场景来自已审定定义。候选不能通过把可点击角色改成纯展示、把条件改为恒假或只生成禁用实例来删除要求。条件使用引擎提供的命名状态和有限逻辑表达式，禁止任意 BooleanSupplier 或业务回调决定是否免除视觉要求。角色降级、条件变化与场景删减属于设计差异。

每个条件触发要求必须有条件成立与不成立的可执行见证；若条件在目标环境无法触发，报告未覆盖或不适用的审定依据，不计为通过。获批角色基线要求的能力不能由配方自行标为不适用。检查实际可交互能力与角色是否一致，避免“条件为空所以没有效果也合法”。

最小场景矩阵按组件实际能力展开：

| 能力或变化 | 必需验证 |
| --- | --- |
| 可点击／聚焦 | 启用时进入与离开、按下与释放、取消及焦点变化；禁用场景验证不响应。 |
| 动画 | 起点、非零中间阶段、终点和适用的反转／中断；只截结束帧不算覆盖过程。 |
| 嵌套动作 | 内层动作消费事件及反馈归属，父层行为符合已审定叠加规则。 |
| 折叠／滚动／页面切换 | 前后状态、中间态和捕获取消，完整外层进退场及命中。 |
| 文本与自适应 | 空值、换行边界、溢出及窄宽约束；适用的语言与字体角色。 |
| 开放参数与降级 | 参数端点及代表性合法值、非法值拒绝；降级条件成立与恢复。 |

预期状态、轨迹与参考帧来自已审定角色基线、独立标杆及批准的观察规则，不从候选输出反向生成。连续颜色等参数用边界、不变量和代表性样本验证，不声称穷举全部颜色或自动认可所有组合的审美。

固定记录设计版本、候选源码状态、页面、场景、主题、字体资源、视口、GUI 缩放、内容、后端和采样时间。主代理、子代理和 CI 运行同一入口与场景；不得另写一份手绘头栏、纯色背景或关闭动画的近似页面冒充生产合成链。

CPU、隐藏 GL 和真实 MC 仍是不同环境。共享生产页面代码不意味着离屏已证明游戏最终合成正确，报告必须保留对应范围。

### 8.3 视觉回归

固定环境下，对关键材质、状态与动画阶段做图像比较。组件自身与获批参照比较；页面回归使用该页面自己的固定业务场景，不要求不同业务页面整图相同。

现有 CI 会在中文字体与 Arial 间回退，不能直接沿用这一条件建立严格视觉基准。先固定可重复的字体资源、环境和后端，校准正常波动；必要时分别维护明确环境的基准，不随运行机器自动选宽松参照。

容差、裁剪区域和采样点从已认可参照及稳定性测量确定，不预设“看起来差不多”的分数，也不自动重录基准。新基准必须与参照定义区分，不能从迁移后的错误实现生成期望，再用它验证自己。

### 8.4 错误报告

每条诊断至少包含：页面和组件路径、违反的规则、实际来源、期望来源、关联配方、所缺场景或渲染输出，以及合规处理方向。

建议稳定错误类别：未知或未批准定义、非法组合、必需项缺失、页面越权绘制、布局来源非法、素材用途非法、实际行为缺失、视觉偏差、未覆盖入口、未定义降级、待设计审查。错误码用于定位，不能代替可读说明。

图像失败输出同条件参照、候选、差异及必要的动态序列；不得只给一个红色分数或一张无法复现的截图。

### 8.5 构建检查器的独立分发与标准任务

交付独立构建制品 atomlib-frontend-checker，包含 JVM 检查入口、版本协议及薄 Gradle 接入。它属于开发构建工具，不合入三个 Minecraft 运行时 JAR；解析器使用 JDK 编译 API，不因此引入另一套运行时 UI 或任意脚本系统。首版 Gradle 接入沿用 Maven 构建依赖，不强制使用插件门户。

消费者从发布仓库或本地候选 Maven 输入取得检查器和所需公共契约模型，不引用 AtomLib 的 tools 目录，也不复制可随意漂移的检查脚本。坐标版本显式声明，检查协议、设计格式和语义配置进行兼容核对；不匹配时失败，不能偷偷下载最新版补齐。检查器以宿主 Java 工具链执行符号分析，Java 21 源码不得交给只识别 Java 17 语法的工具链。

Gradle 接入注册 frontendContractCheck，接到 check，并在 build 及正式分发／发布产物任务之前执行；本地 assemble 开发候选与草稿可以有独立入口，但产物状态必须可辨别，不能获得正式资格。候选 pending、非零退出、工具缺失、场景缺失和未支持状态须传播到上层任务。

仅安装运行时 JAR 不称为启用前端锁。项目启用需要构建接入、批准来源、宿主入口覆盖和必需场景四项齐全。运行时严格会话还须核对构建生成的正式清单和设计身份；缺少清单不得静默退回自由绘制。旧入口不自动转为严格会话。

在具备完整接线的项目中，已审定 CI 入口先以其既定检查器核对接入配置，再执行候选构建；不能仅依赖候选工作树中可能已被删除的 Gradle 接入来发现自身缺失。删除接入或改用无检查器任务是接入配置变化，必须阻断普通功能验收。CI 入口本身的修改也须单独审查，仍遵守工程约束的权限边界。对一个从未安装检查器、也未采用已审定 CI 的项目，库不能自行控制其构建，只能明确判定其未启用，不承诺“装 JAR 即锁住所有源码”。

发行验收创建无源码目录依赖的干净消费者：只解析候选 Maven 制品，普通 build 对合法页面通过，对越界页面失败；缺接线不被启用检测接受，草稿不能进入正式包。Linux 公共检查与支持的 Windows 原生场景各自执行，不以完整 MC native 库作为运行纯源码检查的前提。

## 9. 文件与模块安排

以下是建议新增位置，不代表已经存在的 API。实施先完成窄原型，再以验证结果固定最小类型集合；不一次性生成大量空壳类。

| 位置 | 责任 |
| --- | --- |
| core/src/main/java/com/atom/lib/frontend/contract/ | 平台无关的族群引用、角色要求、配方和页面契约、依赖解析及诊断模型。 |
| core/src/test/java/com/atom/lib/frontend/contract/ | 缺项、条件、不适用、循环、覆盖、隔离、版本和参数边界测试。 |
| ui/src/main/java/com/atom/lib/frontend/ | 严格页面构建、只读注册表句柄、到既有控件与布局的适配；不暴露原始画布回调。 |
| ui/src/test/java/com/atom/lib/frontend/ | 页面入口、状态转换、输入命中、内容插槽、动态图像和降级验证。 |
| ui/src/main/java/com/atom/lib/design/atomchat/ | 试点需补齐的获批 AC 配方，先核对真实页面，再复用已有实现。 |
| build-tools/frontend-checker/ | 独立发布的检查器与薄 Gradle 接入，仅用于构建；包含源码边界、批准状态、覆盖及诊断协议的测试。 |
| tools/frontend-contract-lock/ | 最小探针和仓库内测试驱动、报告／视觉汇总，不作为消费者唯一能获取的检查器。 |
| tools/verify_frontend_contract_mutations.py | 串行缺陷负例及恢复验证，按实际状态备份，不用 git checkout 恢复。 |
| examples/verification/ | 发行消费者的严格入口探针，验证分发后可用性和旧 API 兼容。 |
| settings.gradle、build.gradle、gradle/module-layout.gradle 及打包脚本 | 接入构建工具子项目及其 Maven 发布；显式区分运行时模块与构建工具，避免根发布遍历或平台打包误混。 |
| .github/workflows/build.yml 与相关 Gradle 文件 | 契约、原生、GL、负例和打包接入；契约或基准变动不得被 docs-ignore 跳过。 |
| docs/wiki/frontend-contract-lock.md、docs/ai-guide.md | 接入、边界、草稿与设计变更指南；更新旧的自由绘制说明，明确适用范围。 |

core、ui 不新增与宿主业务相关的网络或持久化依赖。检测器构建入口接入现有 Gradle；先验证 JDK 自带编译 API 的可行性，不为文本扫描不足直接引入整套新工具链。

宿主项目的设计作者输入、规范化设计包、批准索引、遗留入口清单和场景清单分别具有明确用途；生成结果不手工编辑。存储目录在接入时显式指定，不能用任意目录豁免替代登记。数据清单和语义配置进入构建输入追踪，格式版本不兼容必须在渲染前报告。

## 10. 实施顺序与阶段验收

### 阶段一：标杆清单与最小可行探针

- [ ] 与 AtomChat 当前返工专项协调，确定获批且稳定的参照状态、所选设置子页和复用页签；不在两个会话中并行改同一批文件。
- [ ] 对照真实 SettingsSectionPage、SettingsGroupFrontend、SettingsGroupPaint、SettingsChipBar、SettingsRowText、PageTransitionComposite 及试点涉及的输入组件，列出材质、几何、状态、动效、素材、异常与合成链。
- [ ] 将提取清单与试点场景保存为可审查输入，不把 Lib 当前相似组件直接当作已认可真值。
- [ ] 制作最小源码边界探针：合法页面与业务数值可通过，直接绘制、间接 helper、静态导入和匿名样式必须被拒绝。
- [ ] 在已有路由与同一旧文件中新增分支、外层绘制和未知工厂，验证遗留登记不自动扩张；明确三端宿主入口与源码覆盖清单。
- [ ] 验证独立检查制品可被干净消费者解析和接线，不依赖源码路径；确定检查协议与 Java 工具链选择。
- [ ] 验证规范化结果可确定生成并供运行时读取；冻结批准状态协议、首个语义配置边界、条件见证和单位变换约定。
- [ ] 验证同一真实页面入口可在统一数据与时钟下产出稳定帧，并确认字体、后端及完整页面外层的接入方式。

阶段结果：可行性记录、差异清单、扫描负例、可重复参照及 R1—R7 的最小正反例。若独立交付、遗留变化识别、批准选择或语义兼容无法落地，不能进入功能实现；先修订对应技术设计，不缩窄判据冒充原目标完成。

### 阶段二：契约与严格页面闭环

- [x] 实现平台无关的引用、角色基线、配方、页面允许范围、作用域、参数和降级校验。
- [x] 先用能揭示缺项和来源错误的测试构建红灯，再实现最小解析；不以测试重复常量声明作为验收。
- [x] 建立只读注册表与受约束的页面入口，落到现有 Yoga、控件和 PresentationFrame。
- [x] 将规范化设计包、格式与语义配置、实现绑定及批准索引接入正式／候选状态机，运行时不执行作者声明。
- [x] 接入草稿隔离、正式依赖检查、迁移清单和明确的设计差异报告。
- [x] 接入命名条件、成立／不成立见证、角色能力与场景矩阵；覆盖逻辑单位及所有宿主转换边界。
- [x] 验证页面不能经旧 API、helper 或内容插槽绕过约束；同帧绘制和输入消费同源几何。

阶段结果：一个小型完整场景可运行，合法路径通过，缺项和越界路径稳定失败。旧入口保持兼容，不能把旧消费者通过报告为已受锁。

### 阶段三：真实标杆与复用页面

- [ ] 在协调好的 AtomChat 工作状态中迁移所选标杆页面，按清单保留完整前端，业务行为保持原边界。
- [ ] 复用页面绑定同一获批前端契约，以业务结构差异检验复用能力，不重新画近似组件。
- [ ] 覆盖卡片、输入、图标、实际使用的滚动与折叠、页签完整出入场、焦点和命中；不迁移试点未使用的整个控件库。
- [ ] 输出同候选、同条件的标杆与复用页面对照和关键动态序列，验证降级与合法个性化。
- [ ] 分别检查输入成本和渲染成本，记录环境及范围；离屏耗时不冒充游戏 FPS。

阶段结果：真实消费者从可分发候选 Maven 制品获得能力，无本机源码路径依赖，不要求提前公开发布；两页的生产代码受控场景完整、可复现，但此时不自动取得实机验收状态。试点修改不覆盖其他专项 WIP，也不继承其他会话的部署授权。

### 阶段四：CI、负例与制品

- [ ] 将契约、源码边界、动态和视觉检查接入既有 CI；实际改动触及定义、素材、基准或检查器时必须运行相关检查。
- [ ] 为普通消费者提供明确的构建接入和页面入口覆盖检查；缺接线不能显示为“项目已启用且通过”。
- [ ] 运行第 11 节负例，逐项确认预期规则捕获，检查失败不是由无关编译错误、缺依赖或旧报告造成。
- [ ] 验证三端打包、隔离 Maven 消费者和旧公共 API；制品排除草稿、开发素材和本机路径。
- [ ] 验证构建工具随 Maven 输入可获取且不进入运行时 JAR，普通 check / build 与正式打包正确传播待批准及失败结果。
- [ ] 用旧设计包和独立参照检查机制升级，验证同 ID 改材质系数／动画解释不会被当成无设计影响。
- [ ] 集中独审一次，修复后只复核受影响代码和场景。给用户展示真实参照及候选，保留实机验收边界。

阶段结果：检查可在受支持环境重复执行，缺陷会红、恢复会绿，候选与验证记录对应；没有把普通样例通过当作真实项目验收。

### 阶段五：已选试点的实机验收

- [ ] 先给用户展示同候选的受控结果与未覆盖清单；部署和启动仍需后续明确授权，本方案不触发这些动作。
- [ ] 在阶段一明确的平台／实例运行完整标杆与复用流程，核对最终合成、图标、GUI 缩放、输入与焦点、hover / press / ripple、滚动、折叠和完整出入场；只列试点实际具备的能力。
- [ ] 由用户确认观感和关键交互；发现失败回到受影响实现与检查，不以离屏通过覆盖实机否决。
- [ ] 按第 12.1 节标注最终状态及其环境。其他加载器或渲染组合若没有实际验证，继续列为未实测，不宣称三端实机通过。

阶段结果：已选真实试点达到 TRIAL_ACCEPTED。等待授权、实例或用户操作时可交付 CANDIDATE，但不标记完整试点或 0.6.0 验收完成。

## 11. 必须证明有效的负例

| 缺陷 | 预期拒绝点 |
| --- | --- |
| 页面新增卡片材质或局部颜色覆盖 | 定义来源、页面允许范围或设计变更检查。 |
| 用合法基础成员拼出未批准的新卡片 | 配方组合校验。 |
| 配方漏写可点击卡片必需 hover | 角色完整性检查。 |
| 声明有 hover / 水波但实际不执行或不绘制 | 输入、动态和渲染验证。 |
| 页面手算坐标，或把计算移到 helper | 严格入口与符号依赖检查。 |
| 私加间距档位、偏移、字号或尺寸公式 | 视觉参数来源与布局规则检查。 |
| 禁止任意实际尺寸，误伤长文本一至四行自适应 | 合法正例必须通过，不能以一律禁数值换取假安全。 |
| 新增页面却不登记、漏掉隐藏或折叠必需分支 | 路由、工厂、依赖和场景覆盖检查。 |
| 换另一图标集，或仅保持画布尺寸而让实际图形偏移 | 素材来源、图形边界和渲染检查。 |
| 用业务图片覆盖材质或任意页面区域 | 内容插槽及层级范围检查。 |
| 绘制和命中在动画中使用不同变换 | 实际输入落点与渲染场景验证。 |
| 预览关闭动画、改用手绘页面或另建时钟 | 生产入口及必需动态场景检查。 |
| 模糊失败时切到未经定义的默认皮肤 | 降级契约与异常场景检查。 |
| 草稿通过源码或资源间接进入正式页面或制品 | 依赖与打包检查。 |
| 扫描零命中、缺图、全跳过或复用陈旧报告 | 检查完整性失败，不返回成功。 |
| 修改规则、检查器或重录基准掩盖偏差 | 明确输出设计／验收规则变更，不能作为普通页面修复自动认可。 |
| 只有运行时 JAR，或删除 Gradle 接入后仍声称已启用 | 干净消费者与已审定构建接线检查拒绝；未安装项目明确为未启用。 |
| 在同一旧文件／旧路由中增加界面或外层绘制 | 入口结构及 LEGACY_UI_CHANGED 检查，旧豁免不扩张。 |
| 将批准来源改成当前候选，并尝试把候选通过当正式通过 | 普通／候选状态机阻断，批准来源变化待设计审查。 |
| 保持设计 ID 和参数不变，改变材质系数或动画解释 | 语义配置兼容检查与旧设计独立参照失败。 |
| 构建和运行环境不同导致同版本设计变化 | 规范化结果、作者输入限制与运行资源一致性检查。 |
| 把必需 hover 的条件改成恒假，或测试只生成禁用实例 | 角色基线、条件正反见证和独立场景矩阵失败。 |
| 使用合法令牌却重复应用 GUI 或内容缩放 | 单位边界与真实绘制—命中场景失败。 |
| 仅凭项目编译或离屏通过便报告实机试点完成 | 验收状态缺少 TRIAL_ACCEPTED，完成条件不满足。 |

除负例外，必须保留以下正例，避免以过度禁止换取假安全：未修改的遗留页面仍可工作；业务数值与获批自适应正常；声明参数在合法范围内变化；界面截图作为普通头像合法；已批准图标集合内的新选用不逐张请求批准；项目机制升级继续解释原语义配置。

修改实际源码的变异必须串行执行，以当前字节备份并在 finally 恢复，核对用户原有状态；不得用整仓回退。检查器级负例优先使用隔离 fixture，减少对共享工作区的写入。

## 12. 验收命令与证据范围

现有可复用命令包括根目录 gradlew.bat :core:test :runtime:test :ui:test --no-daemon --console=plain，以及各平台目录的 hiddenGlTest。字体按阶段一确定的固定资源显式提供，不能把未校准的系统字体回退用于视觉硬门槛。

打包与消费者沿用 tools/run_packaging.py all --jobs 1、tools/test_verify_artifacts.py、tools/test_verify_consumers.py 及既有原生检查。新增 Gradle 入口建议命名为 frontendContractCheck，必须在阶段二实际接线后才可列为可执行验收命令，不能现在宣称已有任务。

新增检查器与变异命令在阶段一确定构建原型后固化到阶段结果和 CI，不用未验证的函数签名或虚构命令冒充实施说明。

每项报告保留命令、执行时间、候选、范围、失败／跳过、缺失场景和产物位置。记录需要能够辨别实现、设计、环境与验收目标是否改变，不把记录机制扩大成独立信任系统。

0.6.0 完成条件：D01—D20 均有对应实现或明确流程；构建检查器可独立获取并强制接线；规范化设计、批准状态及语义兼容检查成立；真实两页闭环达到第 12.1 节 TRIAL_ACCEPTED；全部规定正反例通过相应预期；适用公共、原生、三端打包、消费者与视觉检查通过；独审阻断项关闭。未跑试点游戏、缺用户实机验收或仅有离屏结果时，交付状态为候选，不称 0.6.0 完整验收完成。

### 12.1 消费者、场景与实机的分层状态

| 状态 | 需要的证据 | 可以声称的范围 |
| --- | --- | --- |
| DISTRIBUTION_VALID | 干净消费者仅依赖分发候选，构建及正反例通过，检查器和运行时制品均可获取。 | 仅说明分发接入成立；不代表真实页面动态表现。 |
| SCENARIOS_VALID | 真实页面生产入口在固定输入、字体、视口、后端和时钟下通过状态、视觉及异常场景。 | 仅说明所列受控场景成立；不是游戏最终合成或实机输入认证。 |
| TRIAL_ACCEPTED | 前两层成立，且用户在明确候选、平台／实例中验收已选两页的最终合成与关键交互。 | 已选真实试点完成；不能扩大为所有游戏、加载器或第三方渲染组合均通过。 |

三个层级分别记录，不用总测试数或一个绿色状态替代。批准状态与验证层级也是两条独立轴：设计候选即使场景通过，也仍需完成第 7 节设计晋级，才能用于正式页面。

阶段一选择与当前 AtomChat 稳定基准相符的首个实机平台，至少一个明确的平台／实例必须完成试点。三端构建、分发、输入适配自动化及适用 hidden GL 仍是发行要求；并不默认要求用户逐个测试全部加载器和渲染组合，也不将单平台结果冒充三端实测。具体实例和操作时机按后续授权核对，不提前部署或启动。

实机最小流程包括实际输入与编辑、指针和焦点、不同 GUI 缩放、页面及页签切换、实际存在的滚动／折叠、图标和正常材质，并检查动画期间的命中与最终外层合成。可控故障与全部降级先由自动化验证，无法在实机安全触发的异常不冒充已实测。性能另记录同条件输入和帧成本，不能以此替代观感确认。

若项目所有者之后明确允许带已知限制交付，单独记录被豁免的验收范围和交付结论；这不是普通代理可自行采用的默认降级路径。

## 13. 实施前必须核实的技术问题

下列问题由源码调查和最小探针解决，不把普通技术细节继续变成用户选择题：

1. 独立构建制品、薄 Gradle 接入和宿主 Java 编译工具链的可行性，以及跨 helper、同文件新增入口和外壳变化的识别。失败时修订严格 API 或分析入口，不能静默退回仅字符串扫描。
2. 真实设置页与 Lib 现有控件的完整行为差异，尤其折叠、页面外层出入场、输入几何和素材；不能以共享 token 代替差异盘点。
3. 生产页面如何在离屏、隐藏 GL 和 MC 宿主中共用入口，以及每层仍需单独验证的合成边界。
4. 规范化设计包的确定性解析、格式与运行资源一致性，以及第 7 节已审定来源、候选状态和晋级顺序的具体接线。禁止把这些技术问题重新解释成“工作树自述已批准即可”。
5. 当前返工后的 AtomChat 哪个稳定页面状态适合担任标杆，以及试点涉及的代码归属、平台接缝与首个实机平台／实例；按第 12.1 节固定验收范围。
6. 首个语义配置的实现绑定、旧配置回归、条件见证与单位转换，确保参数合法不代替行为或几何正确。

这些核实不改变已选产品边界。若发现必须扩大范围、引入新依赖或改变架构，先带具体证据更新本方案；普通实现选择自行处理。

## 14. 保证的适用范围

前端锁能约束已经建模的来源、组合、完整性和行为，并对固定场景的视觉偏差阻断。它不能自动证明新美术好看，也不能证明所有未建模的状态都没有遗漏。

初始契约必须从获批真实页面建立；新增能力同步补充基线和场景。整体编排审美、运行环境差异和真实游戏观感保留各自验收。以“全部检查通过”代替这些判断，属于错误使用本方案。

## 16. 后续授权补充：声音与易漏维度

用户在实施过程中明确补充：参照页面的 UI 声音属于完整前端；只搬画面、遗漏声音同样不能通过。此要求扩展 D07／D08／D18／D20 的覆盖，不推翻 D01—D20，也不授权一般音频引擎、触觉或整套无障碍系统。

声音契约必须描述：命名输入／业务结果事件到声音资源的绑定、发生阶段、所属音量通道、音量与音高及允许的派生关系、事件仲裁及去重、实际存在的节流、取消与中断，以及按状态／偏好明确无声。没有时间节流或延迟队列的参照应明确“不适用”，不能创造一套新声音规则；参照缺少取消能力时报告未支持，不虚构已经实现。

core 只持有平台无关的数据／受控音效意图与契约，宿主负责注册、资源解析及实际输出。三端适配消费同一命名事件语义，映射到实际 SDK 的 SoundEvent 与通道；不能由页面任意传资源或播放参数。声音算法与资源变化同样属于设计／语义版本变化。

验证必须覆盖真实输出适配链：资源事件注册和声音资源可解析、实际发出的事件顺序／次数、资源、通道、音量、音高和时机，以及重复动作、取消／禁用／静音等适用场景。只验证声明、调用文本或画面不能证明有声音；边界 spy 需放在实际宿主适配输出端。声卡、游戏混音和最终听感仍需实机，离线解码不冒充听感通过。

按实际参照启用下列能力盘点，并给每项标记已有且需继承、经批准不适用、未支持或待核实；空白不能自动视为不适用：

- 指针状态、tooltip 内容与出现／消失延迟。
- 键盘焦点、快捷键、默认动作、焦点恢复。
- 文本编辑、IME 组合输入、剪贴板、撤销／重做。
- 加载／空／错／禁用状态及反馈。
- 返回后的滚动、选中、草稿和折叠状态恢复。
- 完整退场、中断、反转、捕获取消。
- GUI／内容缩放、语言／字体及用户静音／减少动态偏好。

这些条目是覆盖清单，不自动成为新增功能。展示卡片可不适用编辑和声音；操作系统 IME、未采用的 tooltip 或不存在的用户偏好不得冒称已支持。选定标杆后，按实际能力建立场景矩阵。
